# 本番の非機能目標（承認用草案）

最終更新：2026-11-20
状態：**草案（承認待ち）**。承認後に計画 E1〜E5 を「未定義」から「確定」へ移す。

## 1. 性能・容量

| 項目 | 目標（案） | 根拠・前提 |
| :-- | :-- | :-- |
| 同時利用者 | **10名**（ピーク） | 現場代理人＋本社＋ITで同時利用する想定 |
| API レイテンシ | p95 **500ms** 以内（ローカル/Tunnel経由の通常操作） | 計算エンジンはローカルで軽量。単一ホスト前提 |
| 3D初期表示 | **5秒以内**（参考PC: Core i5 / 内蔵GPU） | 現行はCanvas2Dフォールバック。実3DGSは別途 |
| 監査一覧 | 200件表示 **1秒以内** | 現在 80件前後で実測1秒未満 |
| データ量 | 監査 10万件 / レポート 1万件まで | 単一PostgreSQL。超える場合はパーティション等を検討 |
| 計測方法 | `scripts/` の負荷試験（未実装）で確認 | 供給後、E2の受け入れ条件に接続 |

## 2. 可用性・運用

| 項目 | 目標（案） | 備考 |
| :-- | :-- | :-- |
| 稼働率 | 平日 08:00–18:00 で **99%** | 単一ホスト・計画停止除く |
| 計画停止 | 事前告知のうえ **15分以内** | systemd再起動で概ね10秒 |
| RPO（目標復旧時点） | **24時間** | 日次バックアップ（03:10） |
| RTO（目標復旧時間） | **1時間** | 復元訓練の実測は数秒〜数十秒（小規模DB） |
| 監視 | 5分間隔のhealthcheck、失敗時は記録 | 通知先（Webhook等）は承認後に接続 |

## 5. セキュリティ

| 項目 | 目標（案） |
| :-- | :-- |
| 認証 | Cloudflare Access（メールOTP）必須。未認証は302 |
| 認可 | ロール割当ファイルで制御。未割当は403＋監査 |
| 秘密 | env 0600・リポジトリ非搭載・secret-scan 0件 |
| API | 認証必須（セッション/Bearer）。CORSは許可Originのみ |
| レート制限 | 認証 10回/分・API 20回/分（既定） |
| AI | 予算・レート・出力契約・監査（AI_CALL） |
