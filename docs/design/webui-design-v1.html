1. 目的・利用者・MVP範囲

Why / Who / What / Out

解決する課題

夕方以降に集中する写真整理・Excel集計・帳票作成を減らし、人が「確認・判断・現場」に時間を使えるようにする。判断の根拠は日付つき3Dと監査ログで残す。

提供する価値

3D現場ビュー上でAIが計測・判定・下書きを作成。数値は計算エンジンが決定し、確定は権限を持つ人が承認。全操作はハッシュ連鎖の監査ログに残る。

利用者

ロールできることできないこと
現場代理人・所長（manager）AIタスク実行、下書きの確認、承認・却下、監査ログ閲覧—
現場担当者（staff）AIタスク実行、下書きの閲覧、レポート閲覧承認・却下（403 + 監査ログにDENY）

MVPに含める

3D現場ビュー

解析的サンプル地形のCanvas2D描画、視点プリセット、レイヤ表示、ヒートマップ、人物匿名化。

AI下書き

出来形管理・安全離隔の2タスク。決定的計算エンジンの結果から帳票ドラフトを生成。

承認・監査

承認待ち一覧、承認/却下、レポート登録、追記専用の監査ログとハッシュ連鎖検証。

MVPに含めない（今回の対象外）

  • 実3DGS生成（GPUパイプライン）、実点群/LiDAR取込、WebGPUレンダラ
  • 実LLM/computer-use API接続（Claude / OpenAI）、AIゲートウェイ
  • Entra ID SSO、Teams通知、DirectCloud/SharePoint、施工管理・原価連携
  • 本番正式環境への配備、複数テナント、全社KPI、モバイル最適化

2. 主要フローと受入条件

縦断スライス：画面 → API → PostgreSQL → 再読込

Flow 1：出来形管理（主フロー）

現場を開く→ AIに「出来形管理」を依頼→ 3D上で計測・ヒートマップ・注記→ 帳票ドラフト生成→ 人が承認→ レポート登録・監査記録→ 再読込で永続確認
項目内容
開始条件ログイン済み。現場 site-a を選択。
操作「盛土 出来形管理」タスクをクリック。AIの6ステップを表示。
期待結果評価点数2,688点、合格率93.4%、最大不足-0.59m等の下書きが生成され、承認待ちに登録される。
保存データruns（結果・ステップ）、approvals（pending）、承認時にreports、audit_events。
エラー時API失敗はトーストで通知し、実行前の状態を保持。承認失敗はモーダル内にエラー表示。
受入条件承認後にレポートが一覧に出る。ページ再読込後も残る。監査ログが検証OKになる。

Flow 2：重機 安全離隔チェック

旋回中心・バケット先端・作業員3名の位置を60秒分（0.2秒刻み）走査。危険エリア半径7.5m、最小離隔5.0m（W-02）、侵入時刻4.2秒を算出。アラート送信・旋回停止は人の承認が必要。

Flow 3：承認・監査

承認一覧で下書きを確認し、承認/却下。判断は監査ログに追記され、ハッシュ連鎖を再計算して検証できる。監査ログはDBトリガでUPDATE/DELETEを拒否（追記専用）。

数値の責任分界：距離・体積・合格率は src/shared/measurements.ts の決定的計算エンジンが算出します。AI（デモ）は手順と操作を担当し、数値を作りません。

入力エラー：ログインの認証失敗、承認の二重判断409、権限不足403、タスク不正400を個別に表示。

  • PCブラウザ中心。スマートフォンの詳細最適化は対象外。

7. API・DB・認証・監査

認証

  • メール + パスワード（scryptハッシュ）。セッションはsas_session Cookie（HttpOnly, SameSite=Lax）とBearerトークンの両対応。
  • Cloudflare Pages からトンネルAPIを呼ぶ場合は Authorization: Bearer を使用（クロスオリジンCookieを回避）。
  • 承認は manager のみ。権限なしは403 + 監査ログDENY。

API

MethodPath用途
POST/api/auth/loginログイン（user + token）
POST/api/auth/logoutログアウト
GET/api/bootstrapユーザー + ダッシュボード
GET/api/sites/:id現場詳細・版
POST/api/sites/:id/runsAIタスク実行（result/steps/approval）
GET/api/approvals承認一覧（status）
POST/api/approvals/:id/decision承認/却下 + レポート登録
GET/api/sites/:id/reports現場の確定レポート
GET/api/audit / /api/audit/verify監査ログ + ハッシュ検証
GET/api/healthヘルスチェック（DB）

DB（PostgreSQL）

テーブル主な列役割
usersemail, password_hash, rolemanager / staff
sessionstoken_hash, user_id, expires_atセッション
sites / site_versionsmodel jsonb, progress現場・4D版
runstask, result jsonb, steps jsonbAI実行結果
approvalsstatus, risk, metrics, decided_by人の判断
reportsverdict, metrics, findings確定レポート
audit_eventsseq, actor, type, prev_hash, hash追記専用の監査ログ
監査ハッシュ：hash = SHA-256(prev_hash | createdAt | actor | type | detail)。全件再計算し、prev_hashとhashの連鎖を検証。UPDATE/DELETEはトリガで拒否。

9. 受入条件

  1. ログイン（manager / staff）ができ、未認証は保護画面からリダイレクトされる。
  2. ホームに3現場・KPI・承認待ち・監査ログが表示される。空のときはEmptyState。
  3. 3D現場でCanvas2Dの現場ビューが表示され、視点・レイヤ・ヒートマップ・匿名化が操作できる。
  4. 出来形AIタスクを実行すると6ステップが表示され、承認待ちの下書きが生成される。
  5. managerが承認するとレポートが登録され、再読込後もDBから復元される。
  6. staffは承認できず、403 + 監査ログDENYとなる（UIはボタン無効 + 注記）。
  7. 監査ログがハッシュ連鎖検証OKになり、DBのUPDATE/DELETEは拒否される。
  8. 主要なLoading / Empty / Error / Success状態が実装されている。
  9. 型検査・Lint・Unit・API Integration・E2E・Buildが成功する。
  10. Cloudflare Preview上で主要フローを操作できる。

11. 承認のお願い

本仕様（v1.0）は、既存の承認済みプロトタイプ V2.1 のデザイン言語をMVP範囲に適用したものです。以下のいずれかでご判断ください。

  1. この内容を承認し、追加改修・運用検証を進める — 現状の実装を正として、Cloudflare Previewでの確認とBacklog整理を継続。
  2. 修正してから再提示する — 画面・文言・優先順位の修正点をご指定ください。
  3. 今回は保留する — 実装は現状のまま停止し、設計のみ保管します。

承認範囲：画面構成、UI/UX、状態、API/DB契約、デモ/実接続の境界。本番配備・費用・破壊的DB操作は含みません。
