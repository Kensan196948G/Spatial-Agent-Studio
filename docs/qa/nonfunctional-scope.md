# 非機能の適用範囲（性能・アクセシビリティ・クロスブラウザ）

決定：**2026-11-20（ユーザー選択 5）** — 本プレビューMVPでは以下を**対象外**と明示する。
「未検証のままPASS扱い」にはしない。QAのリスク項目 RR-03 は「対象外（明示）」として閉じる。

## 1. 対象外とする項目

| 領域 | 対象外の内容 | 代替（実施済み） |
| :-- | :-- | :-- |
| 性能・負荷 | 同時接続数、スループット、p95/p99レイテンシ、長時間連続稼働、GPU/描画負荷の計測 | 単一利用のプレビュー。ヘルスチェックとスモークで機能到達性のみ確認 |
| アクセシビリティ | WCAG 2.x 準拠監査、スクリーンリーダー実機検証、キーボード完全操作、コントラスト比の全画面測定 | 主要ボタンは`<button>`、フォームは`<label>`、`aria-label`を一部付与。監査は未実施 |
| クロスブラウザ | Chrome/Firefox/Safari/Edgeの実機マトリクス、モバイル端末 | デスクトップChromium（Playwright）のみ。READMEにも「PCブラウザ中心」と明記 |
| 可用性・SLO | 稼働率目標、監視・アラート、自動復旧 | プレビューはホスト稼働中のみ。APIはnohup/systemd（人間運用） |
| セキュリティ診断 | ペネトレーションテスト、依存の継続監視 | secret-scan・監査ハッシュ連鎖・Access OTP・CORS/ヘッダーで基礎的な統制 |

## 2. なぜ対象外にするか

- 本プロジェクトは**個人利用MVPのプレビュー**であり、利用者は関係者数名・デモデータのみ。
- 性能目標・a11y基準・対応ブラウザ表が**未定義**のまま「検証済み」と主張すると、根拠のない品質表示になる（QAの指摘どおり）。
- 本番昇格時には、これらは**受入条件として定義が必要**（下記）。

## 3. 本番昇格時に必要になる定義（引き継ぎ）

| 項目 | 決めること |
| :-- | :-- |
| 性能 | 同時利用者数・撮影データ量・許容レイテンシ（例：3D初期表示◯秒、API p95◯ms） |
| 負荷試験 | 対象シナリオ（ログイン/3D表示/承認）と実施環境（preview相当） |
| a11y | 準拠レベル（例：WCAG 2.1 AA）と監査方法（自動＋手動） |
| ブラウザ | 対応表（例：Chrome/Edge最新、Safari 17+）とモバイル方針 |
| 可用性 | SLO・監視・アラート・バックアップ/リストア訓練 |

## 4. QA上の扱い

- リスク RR-03 は「未検証」ではなく**「対象外（明示）」**として記録する。
- テストレポートの品質判定では、これらを**PASSとして数えない**（v3の記載どおり）。
- 対象外を解除する条件：上記§3のいずれかが定義され、検証手段が用意できた時点。
